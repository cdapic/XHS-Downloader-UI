## 二、问题清单

> 编号规则：IS-xx。等级：P0 阻断 / P1 体验 / P2 工程。

### IS-01 【P0】生产样式依赖公网 CDN，构建产物内无 CSS

| 项 | 内容 |
|---|---|
| **证据** | ①`dist/index.html` 第 7 行：`<script src="https://cdn.tailwindcss.com"></script>`；②`dist/assets/index-BMcF8Ye-.js` 中检索 `tailwind` → **命中 0 次**；③仓库内**不存在** `tailwind.config.js` / `postcss.config.js`；④`tailwindcss@3.4.1`、`postcss@8.4.35`、`autoprefixer@10.4.17` 仅存在于 `devDependencies`，`vite.config.ts` 未引用 |
| **事实** | 使用的是 Tailwind **Play CDN**（官方明确标注"仅用于开发，请勿用于生产"）。样式在**浏览器运行时**由该脚本即时生成，因此完全不在构建产物内 |
| **影响** | ①**NAS 内网/断外网访问 → 全站无样式白板**，而项目自述为"部署在我的 NAS 上自用"，与该前提直接冲突；②公网 CDN 抖动或不可达 → 随机白板；③运行时生成样式 → FOUC（首屏无样式闪烁）；④无法 purge，全量样式在浏览器端加载，浪费带宽 |
| **等级** | P0 |
| **归属** | v1.1 FR-01 |

### IS-02 【P0】解析与下载均不可取消，无超时

| 项 | 内容 |
|---|---|
| **证据** | `services/xhsService.ts` 全文 34 行，仅用 `fetch`，**无 `AbortController`、无 `signal`、无超时**；`utils/downloader.ts` 全文 78 行同理 |
| **事实** | 唯一的中断方式是刷新整个页面 |
| **影响** | ①后端慢或卡住时，用户只能刷新页面并丢失输入；②批量场景（v1.2）下不可取消将直接导致产品不可用；③无超时意味着"永远转圈"，用户无法区分"慢"与"死了" |
| **等级** | P0 |
| **归属** | v1.1 FR-02 |

### IS-03 【P0】错误不分类型，用户无法自助排查

| 项 | 内容 |
|---|---|
| **证据** | `types.ts` 第 40 行：`ParseStatus = 'idle' \| 'loading' \| 'success' \| 'error'`，仅四态；`App.tsx` 第 65-70 行的 `catch` 与第 61-64 行的非空判断均落到同一个 `status = 'error'`，共用同一张错误卡片 |
| **事实** | 网络层错误（CORS / 5xx / 容器挂掉）与后端业务错误（HTTP 200 但 `data: null`）在 UI 上无法区分；仅能靠 `result.message` 是否为空来间接推断 |
| **影响** | 每次故障都要查 `docker logs` 才能定位，运维成本最高的一项。`memory-bank/techContext.md` 甚至为此专门写了一节「拿不到数据时先看后端日志」——说明这个痛点已经被迫用文档弥补 |
| **等级** | P0 |
| **归属** | v1.1 FR-03 |

### IS-04 【P1】无法批量提交，textarea 仅单条语义

| 项 | 内容 |
|---|---|
| **证据** | `App.tsx` 第 36-71 行 `handleParse` 将 `inputText.trim()` 整体作为**一个** url 提交（`xhsService.ts` 第 20 行 `url: input`）；第 14 行 `inputText` 为单一字符串状态 |
| **事实** | 采集 20 篇需重复 20 次「粘贴 → 解析 → 下载」 |
| **影响** | 追热点期的时间成本被放大 20 倍；这是 `memory-bank/tasks.md` 中「批量粘贴」待办的来源 |
| **等级** | P1 |
| **归属** | v1.2 FR-09/10/11 |

### IS-05 【P1】无输入校验

| 项 | 内容 |

| **影响** | ①误贴任意文本 → 徒劳的网络请求与后端负载；②超长文本（如误贴整篇文章）会完整进入请求体 |

### IS-06 【P1】ZIP 内图片扩展名硬编码为 `.png`

| 项 | 内容 |
|---|---|
| **证据** | `utils/downloader.ts` 第 50 行：`const ext = type === 'video' ? 'mp4' : 'png';`。对比 `components/MediaGrid.tsx` 第 22-27 行的 `getExtension()` **已实现**扩展名推断，但 ZIP 路径未复用 |

## 五、盘点结论

1. **功能层不缺东西**：单篇链路的完整度已相当高，所有已登记待办都不是阻断性的。
2. **地基有硬伤**：IS-01（CDN 依赖）与自托管定位直接冲突；IS-02/03 让故障无法自助排查。
3. **文档层在漂移**：README 与 memory-bank 共 6 处描述与实现不一致，其中 3 处是"待办其实已做完"。
4. **工程层欠债**：零测试、文件偏大、死配置。
5. **真正的缺口不在代码里，而在方向上**：产品缺少"下载之后"的环节——这正是主方案推荐「个人内容素材库」方向的依据。
